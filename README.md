# Notification Platform

Домашнее задание № 4: «Требования и архитектурное мышление», практика 8.2, Т-Образование.

Автор: Михаил Осипов. Дата: 17 ноября 2026 года.

Работа посвящена проектированию централизованной платформы уведомлений онлайн-банка. Репозиторий содержит требования, архитектурный RFC и диаграммы; программная реализация сервиса в условии не требуется.

Согласованный стек возможной реализации: **Kotlin + Spring Boot**, **Kafka**, **PostgreSQL**; локальные контейнеры — **Podman**. Служебные скрипты Python и shell только пересчитывают оценки и строят диаграммы, они не являются сервисами платформы.

## Основные решения

1. Базовая нагрузка — 30 млн уведомлений в сутки: 3 млн DAU × 10. Также рассчитан сценарий 100 млн в сутки, если уведомления получают все 10 млн MAU.
2. Критичные уведомления имеют отдельную зарезервированную пропускную способность. Кампания на 1 млн получателей не должна задерживать сообщение о списании.
3. Выбран вариант 1: Kafka + PostgreSQL и собственный оркестратор. Альтернатива 2 использует Temporal для управления критичными процессами; Kafka остаётся для массового потока и статусов.
4. Доставка считается подтверждённой по сигналу получателя/канала, а не по HTTP 200 от провайдера. Семантика подтверждения для push, SMS и email явно различается.
5. Повторная обработка одного запроса не создаёт новую логическую нотификацию. Полностью исключить два внешних сообщения при неопределённом исходе отправки и failover невозможно без поддержки каналов; для критичных уведомлений приоритет отдан доставке.
6. Маркетинг и сервисные уведомления отключаемы. Критичные сообщения о движении денег и безопасности отключить целиком нельзя; порядок доступных каналов настраивается.

## Воспроизведение

Расчёты используют только Python 3:

```sh
python3 scripts/calculate_load.py
```

Готовые диаграммы открываются без дополнительных программ. Для их пересборки нужны Java 17+, `curl`, `python3` и доступ к Maven Central при первом запуске:

```sh
sh scripts/render_diagrams.sh
```

Скрипт загружает PlantUML 1.2026.10, проверяет SHA-256 и использует встроенную библиотеку C4 и движок Smetana. Исходники диаграмм не отправляются внешним сервисам. Можно использовать заранее загруженный JAR: `PLANTUML_JAR=/absolute/path/plantuml.jar sh scripts/render_diagrams.sh`.

## Границы результата

Все SLA, квоты, цены в примерах и сроки хранения, отсутствующие в условии, являются проектными допущениями. Расчёт мощности не заменяет нагрузочные испытания. Архитектура рассчитана на отказ узла или одной зоны; одновременная потеря региона и всех каналов выходит за её гарантии.

RFC следует предоставленному шаблону `rfc_template-eea98023-983f-40ce-a6cc-59afc8796642.md`: метаданные, контекст, продуктовый анализ, сценарии, статистика, требования, варианты с этапами/ресурсами, сравнение, выводы, связанные задачи и приложения. Дополнительно включены ASR, гарантии, отказы, внедрение и критерии запуска.
